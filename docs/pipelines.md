# Pipelines

Create agents in the **Agents** UI before building a pipeline. With no agents, pipeline creation is disabled. Agent definitions are stored in `.baton/agents/`; each agent directly selects its provider/model and credential. Runtime/provider/model selection never belongs on a step.

A pipeline is an ordered graph of agent, human-decision, and shell steps. Its `maxAttempts` defaults to 50 for new runs and must be an integer from 1 to 1000. This global limit counts every started visit, including agent, shell, and human steps; failed or interrupted attempts count, and human pauses/resumes do not count twice. An optional step `maxAttempts` independently caps visits to that step; when both limits are exhausted, the global limit takes precedence. Exceeding a limit ends the run before another visit starts. The resolved global value is frozen in each new run; editing the pipeline affects only new runs. Legacy managed snapshots without the field remain unlimited, and legacy external work sessions retain their persisted session limit. For agent steps with transitions, Rig and Pi expose a `report_outcome` tool limited to that step's configured outcomes. The tool summary is the authoritative complete handoff; missing decisions trigger up to two same-session follow-ups and then fail the attempt. Sequential agent steps use the final response as handoff and imply `completed`. Existing saved runs keep their recorded handoffs and are not rewritten. Baton records step inputs, outputs, outcomes and handoffs in the run state.

Agent create and update requests validate direct runtime configuration. Credential references are IDs only; secret values are never accepted through pipeline or run APIs. Deleting an agent referenced by a pipeline returns 409 with the pipeline and step to update.

A project may add a commit agent after review and before human approval. That agent inspects and commits task changes in the task worktree; Baton does not create commits. Keep its instructions explicit about excluding session data and unrelated files, and have it call the configured `report_outcome` control tool after committing.
