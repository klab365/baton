# Run token usage and estimated costs

Rig provider usage is collected from each reported model reply and aggregated for the pipeline attempt independently of the bounded activity trace. Unreported counters remain unknown; they are never converted to zero. Models.dev pricing is looked up best-effort with a three-second request timeout and a one-hour in-memory catalog cache. HTTP failures, unknown models, and malformed rates leave cost unavailable without failing the agent run.

The estimator uses models.dev's per-million-token input, output, cache-read, and cache-write rates. Cached input is subtracted from total input before applying the ordinary input rate, then charged using its reported cache category rate. Cost is emitted only when all required counters and category rates are present and the decimal arithmetic is representable; otherwise usage and available rate provenance remain while cost coverage is partial. Persisted provenance includes USD, the per-million-token unit, category rates, source, check timestamp, and a rate snapshot.

These figures are estimates, not invoices. They use the catalog's listed rates and may differ from provider billing because of provider-specific tiers, discounts, hosted tools, or catalog changes. Pricing is currently applied after a runtime attempt returns; persisted token usage and cost estimates therefore become visible after that attempt, not per model turn while it is running. Historical records without pricing provenance remain unknown, not zero. Run list/detail API responses and the CLI `run progress` projection expose the computed `usageSummary`, produced by the same core exact-arithmetic helper and consumed by the Web run page when present. The CLI also includes the latest attempt's `usage` and a `usageObservations` entry for every persisted attempt (with `usage: null` when unavailable). Totals require complete observations with matching currency and price unit; consumers must treat missing observations as unavailable.
